Leggere un frame Modbus a occhio

12 settembre 20268 minuti di letturaProtocolli ed embedded

Prima di parlare di ottimizzazione servono numeri di cui fidarsi. Un inverter risponde con una sequenza di byte, e ogni byte ha un posto preciso.

Il frame

Leggerlo a occhio è il primo controllo che faccio, prima ancora di scrivere qualsiasi codice di decodifica. Ecco una richiesta Modbus RTU scomposta nei suoi campi.

01Indirizzo
dispositivo
03Funzione
lettura registri
00 00Registro
iniziale
00 02Quantità
di registri
C4 0BControllo
CRC16

Leggi due registri a partire dall'indirizzo 0 del dispositivo 1.

Dal lato sistemista. Se il CRC non torna, non è quasi mai colpa del codice. Controllo prima velocità, parità e cablaggio con le masse: risparmia a tutti una giornata di debug applicativo.

Verificare il CRC

Il controllo si calcola in poche righe. I due byte finali del frame sono il risultato, con il byte basso per primo.

Python 
def crc16_modbus(data: bytes) -> bytes:
    crc = 0xFFFF
    for byte in data:
        crc ^= byte
        for _ in range(8):
            crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1
    return crc.to_bytes(2, "little")

crc16_modbus(bytes([0x01, 0x03, 0x00, 0x00, 0x00, 0x02]))  # b'\xc4\x0b'

Dai numeri al modello

Quando i numeri sono affidabili entrano nel problema di programmazione lineare intera mista. Le variabili sono le potenze di ogni ora, i vincoli sono i limiti fisici, l'obiettivo è spendere il meno possibile dalla rete.

minimizza Σ c(t) · P_rete(t) vincoli Σ P_auto(t) · Δt = E_richiesta 0 ≤ P_auto(t) ≤ 3,7 kW P_rete(t) = carico(t) + P_auto(t) − FV(t), P_rete(t) ≥ 0

Il solver trova da solo la finestra migliore. Il mio lavoro è formulare bene il problema; l'implementazione la delego all'IA.
